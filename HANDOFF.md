## 1. What this is

A Solana-only memecoin trading bot that screens tokens, computes technical
indicators across multiple timeframes, generates BUY signals, and simulates
(paper) or executes (live) trades. Built in Python 3, runs on Windows/PowerShell,
venv at `C:\Users\seanf\Documents\trading-bot`.

It is NOT multi-chain. Every component is Solana-specific (Birdeye Solana API,
Jupiter DEX, Helius RPC, SPL tokens, Solana USDC mint). Adding chains = full rebuild.

## 3. Architecture / pipeline

Pipeline scripts in `scripts/`, run in this order (by monitor_loop.py every 15 min):
1. screen_memecoins.py   — 3 screens (momentum, whale_target, lottery), 3 sorts each (volume, liquidity, market_cap or 24h change)
2. watchlist.py          — force-includes specific addresses (data/watchlist.txt) regardless of screens; writes screen='watchlist'
3. rug_check.py          — Birdeye-based rug scoring
4. ingest_ohlcv.py       — pulls 5m/15m/1H/4H/1D candles
5. compute_indicators.py — MACD, Stoch RSI, BB, EMAs 50/200, ATR_14, OBV, VWAP, volume_sma_20
6. whale_risk.py         — top-holder distribution
7. macro_regime.py       — F&G, BTC dominance, stables, Fed
8. strategy.py           — emits signals (entry logic + cooldown)
9. paper_trader.py       — simulates positions, tracks P&L, enforces risk caps

Reporting / ops (run manually):
- daily_report.py         — overnight summary
- go_live_dashboard.py    — readiness check (5 gates)
- balance_reader.py       — wallet balances via Helius RPC
- execution_coordinator.py — LIVE trade execution (manual yes/trade, $30/day cap) — NOT in use during paper run
- backtest.py             — point-in-time replay of live strategy over historical candles
- morning_check.ps1       — runs balance_reader, paper_trader, daily_report, go_live_dashboard in sequence

Execution adapter (6 pieces, verified with a real $1 trade earlier): wallet_loader.py,
balance_reader.py, jupiter_swap_builder.py, tx_simulator.py, sign_submit.py, execution_coordinator.py

## 5. Strategy logic (strategy.py)

Entry requires ALL of:
- 1D higher timeframe bullish (close > EMA50 > EMA200) — note: tokens <200 days old can't satisfy this; strategy has a "no data, skip" path
- 4H bullish
- 1H bullish
- 15m entry trigger (MACD bullish cross OR Stoch RSI exit from oversold OR BB lower bounce)
- 5m close above VWAP

Note: a "valid ATR_14" is NOT enforced as an entry gate. If `indicators.atr_14`
is NULL at entry time, `compute_stop_loss` silently falls back to a fixed 5%
stop below entry. Worth gating in future, but flagged here so behavior matches
code rather than the previous doc claim.

Stops/targets: stop = entry - (ATR_14 * ATR_STOP_MULTIPLIER, ~2.0); target = entry + 2R (2x risk).
Strategy mapping by `screened_tokens.screen`:
- `'momentum'`     -> `'momentum'`
- `'whale_target'` -> `'whale_copy'`
- `'lottery'`      -> `'lottery'`
- `'watchlist'`    -> falls through `strategy_map.get(..., 'momentum')` so it
  trades as the momentum strategy ($19.55/position, 3 max positions)

Cooldown: after a STOP_LOSS or HARD_STOP exit on token X, no re-entry for 24h
(COOLDOWN_HOURS_AFTER_STOPLOSS = 24 in strategy.py). As of 2026-05-22 the SQL
matches both `close_reason LIKE 'STOP_LOSS%'` and `LIKE 'HARD_STOP%'`. Prior
versions only matched STOP_LOSS, so HARD_STOP exits could re-enter immediately.

Suspected core flaw: requiring all timeframes bullish tends to enter near local tops
on memecoins (continuation breakout) rather than pullbacks within trends.

## 6. Risk management (paper_trader.py)

- START_CAPITAL_USD = 100.0; available_capital() = START + realized_pnl - deployed
- open_position() refuses to open if position_size > available_capital (prevents over-deployment)
- MAX_LOSS_PCT_HARD = 0.15 — force-close any position down >15% at check time (HARD_STOP)
- MAX_POSITION_AGE_HOURS = 72 — time-stop any position open longer than 72h (TIME_STOP)
- Mid-trade whale-risk escalation: if a token's whale_risk_score reaches >= 60
  while in a position, close immediately (WHALE_RISK)
- One open position per token (dedupe by address)

These exist because of the "WCOR disaster": before the cap, the bot opened 10
simultaneous WCOR positions on a $100 account; WCOR rugged -93% and the buggy
accounting showed impossible -217% equity / 201% drawdown. Paper data was reset
clean on 2026-05-21 (backup saved as data/memecoins_backup_*.db).

## 11. Environment quirks

- Windows/PowerShell. Writing Python via PowerShell here-strings repeatedly mangled
  nested quotes and $-signs. Reliable method: write the file with proper tooling or
  transfer via base64 + [IO.File]::WriteAllBytes, then verify with `python -c "import ast; ast.parse(...)"`.
- Cosmetic SyntaxWarning on strategy.py line 12 (`\ ` in a docstring) is harmless.
- strategy.py has a BOM; use .lstrip('\ufeff') before ast.parse if checking syntax.
- Computer sleep silently stalls the monitor loop: `powercfg /change standby-timeout-ac 0`
- Windows venv `python.exe` is a launcher stub that spawns the real interpreter
  as a child. When listing processes you will see TWO python.exe per script —
  the launcher (parent) and the real interpreter (child). They share the
  command line. To count actual monitor_loop instances, count MONITOR_STARTED
  lines in `data/overnight.log`, not raw process listings.
